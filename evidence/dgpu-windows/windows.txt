What the profile file says (and why it is the safety argument)
--------------------------------------------------------------

The per-GPU profile holds two sections, and only `[Startup]` is applied at boot:

  [Startup]    CoreClkBoost=    VFCurve=    MemClkBoost=     <- stayed empty all session
  [Profile1]   CoreClkBoost=0   MemClkBoost=0   VFCurve=<12 pairs>

`Apply` never writes this file (checked at 16:54, 16:59, 17:16, 17:17), so every
offset above was runtime-only and none of it could have survived a reboot.
`[Profile1]` appeared only once a profile was explicitly *saved*, and its hex
decodes to the **stock** curve -- twelve (voltage, frequency) pairs:

    450 mV/210 MHz   525/300   600/750   675/1110   750/1380   825/1575
    900/1740        975/1860  1050/1950 1125/2010  1200/2025

so it is a restore point, not a trap. Boot safety rests on `[Startup]` staying
empty, and that is checkable in a file rather than trusted from a tick box.

What each line is worth
-----------------------

- **P1 (core offset -300 MHz) vs P0**: 1267.75 -> 1264.25 MHz at the same
  79.3 W. The slider did nothing. Cross-checked by P1b, which moved the same
  interface: +500 MHz of memory offset landed exactly (6001 -> 6501 MHz,
  confirmed by nvidia-smi's own clocks.mem). So the write path reaches the
  driver, and the core clock offset specifically is ignored.

- **P1b also shows the cost inside the power budget**: at an identical 79.9 W,
  the core clock drops to 1217 MHz once the memory runs +500 MHz faster. The
  80 W ceiling is a real, shared budget.

- **P2 / P2b / P2c are inconclusive, by construction.** The workload itself
  drifts by +-65 MHz (measured inside one untouched load: 1295 MHz over its
  first 20 s, 1230 MHz over its last 20 s), and the plateaus tried there were
  1300 and 1200 MHz -- the same size as the drift, and above or beside the
  natural operating point. They are kept because the two wasted passes are the
  method lesson: a change has to be distinctive, and a cap has to be judged by
  the ceiling, not the mean.

- **P2d + P2e are the decisive pass**, and they are one continuous load
  (17:13:58-17:18:58). It merges here because the plateau was lifted with the
  load still running -- no idle gap to split on. Splitting it by hand at the
  step (17:16:51, one sample, usage never leaves 100 %):

      curve plateau ~700 MHz   n=55   core  670 MHz (660-705)   power 69.34 W   temp 66.0 C
      after Reset, same load   n=15   core 1221 MHz (1155-1275) power 78.72 W   temp 67.3 C

  A 45 % clock reduction bought 12 % of the power. That is a frequency clamp
  keeping the card near its power ceiling, not a voltage map: the voltage is
  still being chosen by the stock algorithm.

- For scale, the same GPU on Linux: `nvidia-smi --lock-gpu-clocks=0,1000`
  holds 1000 MHz at **41 W**. Two OSes, same silicon, very different levers.
