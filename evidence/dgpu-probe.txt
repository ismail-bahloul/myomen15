The lock that works, under a real load
--------------------------------------
Load: evidence/gpuload.cu (`nvcc -O2 -o /tmp/gpuload gpuload.cu; /tmp/gpuload &`).

$ /tmp/gpuload &  sleep 4
$ nvidia-smi --query-gpu=clocks.gr,clocks.sm,utilization.gpu,power.draw --format=csv,noheader
1560 MHz, 1560 MHz, 100 %, 79.81 W
1560 MHz, 1560 MHz, 100 %, 79.58 W

$ sudo nvidia-smi --lock-gpu-clocks=300,1000
GPU clocks set to "(gpuClkMin 300, gpuClkMax 1000)" for GPU 00000000:01:00.0
All done.
990 MHz, 990 MHz, 100 %, 41.17 W
990 MHz, 990 MHz, 100 %, 40.68 W

$ sudo nvidia-smi --reset-gpu-clocks
All done.
1545 MHz, 1545 MHz, 100 %, 79.32 W

$ pkill gpuload

Memory clock lock was also accepted:
$ sudo nvidia-smi --lock-memory-clocks=5000
Memory clocks set to "(memClkMin 5000, memClkMax 5000)" for GPU 00000000:01:00.0

Conclusion: GPU clock locking is accepted *and effective* (80 W -> 41 W at
1000 MHz, under full load). Power limit is not settable. Clock offsets are
blocked by permissions. Voltage is not exposed. So the dGPU offers clock
control -- an underclock -- but no undervolt. State left clean: no lock applied.
